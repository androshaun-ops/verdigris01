我們所做的優化與增強 將 `step` 介面升級，使其能動態接收當前節點 Backlog 與資料生產速率，實現容量感知。
src/conn_mgr/conn_mgr.cpp
已優化重構
實現多線路健康度評估與切換演算法。
核心職責 以磁滯過濾（min_switch_interval）鎖死切換；進行優先級排序。
我們所做的優化與增強 1. 實作 $\ge 2$ 次連續失敗抗噪過濾器，徹底將 Ethernet 擺動歸零。
2. 實作「吞吐量感知優化」：當 Backlog 積壓或當前頻寬不足時，將優先級轉為容量導向算法（Capacity * 1000），主動Failover至LTE避險。

⏱️ 模擬引擎與調度 (Simulation Engine)

此模組模擬單核心 preemptive 調度，透過離散的時序階段（Phases）模擬真實硬體的搶佔行為。

src/sim/simulator.cpp
已優化重構
模擬器的調度大腦，驅動整個 fleet 所有節點的時序運作。
我們所做的優化與增強 1. 修正 Phase 6 發送，改為使用搶佔安全的 `inflight` 狀態統計網關容量。
2. 在尾部增加 Final Flush 機制，確保末梢 committed 資料成功交付。
模擬器每分鐘的 7 階段時序（面試必問！） 請參閱下方時序圖表。
1
Phase 1: ISR 採樣開始 ISR Context (最高優先級)
ADC 中斷觸發，在環形緩衝區分配槽位。
2
Phase 2: Upload 任務啟動 Upload Task (最低優先級)
上傳任務開始執行，捕獲當前 active 鏈路（`inflight_link = active_link`），隨後被搶佔。
3
Phase 3: Probe 任務執行 Probe Task (中優先級)
探針任務運行，更新 Ethernet 探針數據。*(我們將 LTE 一併移至此處更新以避免滯後)*
4
Phase 4: ConnMgr 決策 ConnMgr Task (中高優先級)
連線任務運行，進行最優線路動態選擇，並更新 `active_link`。
5
Phase 5: Probe 任務恢復 Probe Task (中優先級)
原本在此階段更新 LTE，現已在 Phase 3 完成以消除 1 分鐘決策滯後。
6
Phase 6: Upload 任務恢復與排水 Upload Task (最低優先級)
上傳任務恢復，使用 Phase 2 綁定的 `inflight` 連線狀態進行資料推送。
★ 我們的修復：模擬器改以 inflight 狀態統計容量，並動態扣減 Mesh client 使用的網關頻寬，消除併發 Bug！
7
Phase 7: ISR 取樣提交 ISR Context (最高優先級)
ADC 中斷底半部（bottom-half）執行，將採樣數標記為 valid 並 commit。

🧪 單元驗證測試套件 (Verification & Tests)

專案的單元驗證套件。我們成功將其擴充，不僅完美通過前三個基礎測試，還加入了更為嚴苛的自研限流與吞吐量驗證！

tests/test_all.cpp
已優化重構
專案唯一的測試進入點，內置 5 個具代表性的高度確定性單元測試。
已通過的 5 大測試說明 1. **`fleet_completeness_should_be_high_under_noise`**：驗證雜訊下 Ethernet 切換次數小於 60 次（我們改進後為 0 次！）。
2. **`failover_to_lte_when_ethernet_down`**：驗證 Ethernet 斷線時能 failover 至 LTE。
3. **`no_sample_loss_under_excess_capacity`**：驗證容量充足時 100% 交付且 0 積壓。
我們新增的 2 大確定性測試 4. **`mesh_gateway_capacity_limit_enforced`**：驗證當網關頻寬為 1，Mesh 頻寬為 5 時，Mesh 節點無法超出網關真實上傳能力（結果：completeness = 0.5）。
5. **`throughput_aware_failover_prevents_loss`**：驗證當 Ethernet 容量為 1，生產速率為 2 時，節點能自動 failover 到容量為 3 的 LTE，實現 100% 交付！
